# وثيقة استراتيجية المنتج والمواصفات التقنية لمنصة Castov (توجيهات للوكيل الذكي AI Agent)

الهدف: بناء وتطوير منصة **Castov** كمنظومة أدوات متكاملة للمطورين (Web + CLI + MCP Server) تعتمد على استراتيجية النمو بقيادة المنتج (Product-Led Growth - PLG)، مع التركيز الصارم على الخصوصية، السرعة، وتجربة المطور (DX).

---

## أولاً: الركائز التنافسية (لماذا يفضل المطور Castov كزائر؟)

يجب أن تلتزم جميع الأدوات والميزات في المنصة بالمعايير الخمسة التالية:

1. **الخصوصية الصارمة (Zero-Data Logging / 100% Client-Side):**
   - جميع العمليات الحساسة (تشفير، فك JWT، تنسيق JSON، توليد المفاتيح) يجب أن تتم محلياً داخل متصفح المستخدم باستخدام `WebCrypto API` و `Local WASM`.
   - يمنع منعاً باتاً إرسال مدخلات المستخدم النصية أو الأكواد إلى السيرفر في الأدوات الأساسية.

2. **السرعة والتصميم النقي (Linear / Vercel Aesthetic):**
   - واجهة داكنة (Dark Mode) أنيقة، استجابة لحظية (Zero Latency)، وخالية من أي فوضى بصرية أو إعلانات مشتتة.

3. **منظومة متكاملة (Web + CLI + Cursor/Claude MCP):**
   - كل أداة متوفرة على الويب يجب أن يكون لها امتداد أو أمر مكافئ في أداة سطر الأوامر (`castov` CLI) وضمن خادم بروتوكول سياق النموذج (`MCP Server`) ليتمكن الذكاء الاصطناعي في Cursor و Claude من استدعائها مباشرة.

4. **الروابط القابلة للمشاركة الفورية (Virality Loops):**
   - توفير زر `Copy Share Link` في كل أداة لمشاركة النتائج والإعدادات مع الزملاء في Slack أو Discord بضغطة زر.

5. **الاستشعار الذكي السريع (`Ctrl + K` Command Palette):**
   - نافذة أوامر سريعة تكتشف نوع النص الملصق تلقائياً (Token, Timestamp, Base64, JSON, Cron) وتعرض النتيجة فوراً دون الحاجة للتنقل اليدوي بين الصفحات.

---

## ثانياً: محفزات التسجيل (Sign-up Triggers - تحويل الزائر إلى مستخدم مسجل عبر GitHub)

لا نفرض التسجيل لاستخدام الأدوات، بل نجعل التسجيل مفتاحاً لميزات الرافعة (Leverage) والمزامنة:

1. **المزامنة السحابية عبر الأجهزة (Cross-Device Cloud Sync):**
   - مزامنة الأدوات المثبتة (Pinned Tools) ومساحات العمل تلقائياً بين حاسوب العمل والمنزل بمجرد التسجيل عبر GitHub.

2. **خزائن أسرار الفرق المشفرة (Zero-Knowledge Team Vaults):**
   - ميزة للمسجلين تتيح مشاركة ملفات البيئة (`.env`) والأسرار مع الفريق التقني بتشفير `RSA-OAEP` من طرف لطرف بدلاً من إرسالها كنص مكشوف في تطبيقات المحادثة.

3. **الربط مع طرفية الأوامر (Castov CLI Access):**
   - التسجيل يتيح للمطور ربط حسابه بـ `castov CLI` لتحميل التفضيلات، الأسرار، وتشغيل الأدوات المخصصة مباشرة من التيرمينال.

4. **مكتبة الأكواد المحفوظة (Saved Snippets Library):**
   - إمكانية حفظ المخرجات (مثل واجهات TypeScript أو قواعد Regex) داخل مساحة عمل المستخدم عبر اختصار `Ctrl + S`.

5. **التفضيلات الافتراضية للمطور (Developer Defaults):**
   - حفظ إعدادات المطور المفضلة (Timezone، حجم المسافات 2 spaces / Tabs، اللغة المفضلة) لتُطبق تلقائياً على جميع الأدوات في كل جلسة.

## ثالثاً: ميزات تقنية متقدمة مطلوبة للتنفيذ (Core Technical Implementations)

يرجى أخذ الميزات التالية بعين الاعتبار عند كتابة الكود وتصميم المعمارية:

### 1. إثبات الخصوصية العملي (Proof of Privacy / Offline-First Badge)
- إضافة مؤشر بصري (Badge) في واجهة الأدوات الحساسة يوضح أن الأداة تعمل بدون إنترنت: `"Works 100% Offline"`.
- دعم العمل دون اتصال عبر `Service Workers`، مع إمكانية إضافة زر (Offline Mode Toggle) يقطع اتصال الصفحة بالشبكة برمجياً أثناء معالجة البيانات الحساسة لبناء ثقة مطلقة مع المطور.

### 2. سجل العمليات المحلي مع الترقية للسحابي (Smart Local History -> E2EE Cloud Sync)
- حفظ آخر 10 عمليات يقوم بها الزائر تلقائياً في متصفحه عبر `IndexedDB` أو `LocalStorage` بدون الحاجة لتسجيل الدخول.
- داخل قائمة السجل (History UI)، عرض رسالة تحفيزية (CTA) أسفل العمليات العشر: *"سجل دخولك عبر GitHub لحفظ سجلك بلا حدود ومزامنته مع الـ CLI بتشفير كامل من طرف لطرف (E2EE)"*.

### 3. أنابيب الأدوات المتسلسلة (Tool Pipelines / Chaining)
- إضافة زر `"Pipe to..."` (مرر النتيجة إلى...) بجانب زر النسخ في كل أداة، مما يسمح بتمرير مخرجات أداة كمدخلات لأداة أخرى (مثال: `Base64 Decode` -> `JSON Format` -> `JSON to TypeScript`).
- السماح للمستخدم المسجل بحفظ سلسلة العمليات (Pipeline) كأمر مخصص واحد يمكن استدعاؤه من الموقع أو عبر الـ CLI (مثال: `castov run my-custom-pipeline`).

### 4. تجربة تسجيل دخول خالية من الاحتكاك في الـ CLI (Frictionless CLI Auth)
- **إصلاح وتطوير معالجة الوسائط (Arguments Parsing):** يجب أن يقبل أمر `castov login` التوكن بجميع الصيغ المتوقعة دون إرجاع خطأ `Unknown option`، سواء كتب المستخدم:
  - `castov login --token cst_live_xxxx`
  - `castov login -t cst_live_xxxx`
  - `castov login cst_live_xxxx`
- **دعم التدفق التلقائي عبر المتصفح (Device Authorization Flow):** عند كتابة `castov login` فقط بدون معاملات، يقوم الـ CLI بفتح المتصفح تلقائياً للمصادقة بضغطة زر (Approve)، ثم يلتقط التوكن ويحفظه محلياً بأمان.

### 5. روابط المشاركة المشفرة من جهة العميل (Client-Side Encrypted Share Links)
- للحفاظ على مبدأ `Zero-Knowledge` عند مشاركة الروابط:
  - **للبيانات الصغيرة:** ضغط البيانات (باستخدام `lz-string` مثلاً) ووضعها في الـ URL Hash Fragment (`#`) بحيث لا تُرسل أبداً إلى السيرفر في طلبات HTTP.
  - **للبيانات الكبيرة والأسرار:** تشفير البيانات داخل المتصفح (`AES-GCM`)، رفع النص المشفر فقط إلى السيرفر، ووضع مفتاح فك التشفير في الـ URL بعد علامة `#` بحيث يستحيل على السيرفر قراءة المحتوى.

## التعليمات للوكيل الذكي (AI Agent Instructions):
عند طلب بناء أو تعديل أي ميزة في مشروع **Castov**، التزم بهذه الوثيقة كمرجع أساسي للمعمارية (Architecture)، تجربة المستخدم (UX)، والأمان (Security). اقترح دائماً الحلول التي تقلل الاحتكاك (Zero Friction) وتعزز التكامل بين الويب والـ CLI والـ MCP.
